游玩流程流转解析

从启动到每次玩家行动的完整链路

3.1 预处理阶段（离线一次性）

IN
输入：中文小说 .txt
放置于 data/novels/，通过 python extract.py 触发
①
文本清洗 + 分句
preprocessing/segmentation/ — 去噪、标准化、按语义边界分句
②
EventExtractor（LLM）
识别关键叙事事件（冲突节点、转折点），输出 events/[id].json
③
LorebookExtractor（LLM）
提取角色、地点、道具、背景知识，写入 lorebook/ 目录
④
DecisionTextExtractor（LLM）
为每个 Event 生成面向玩家的"决策文本"摘要
⑤
7阶段实体状态转换分析
  • Stage 1 EntityScanner — 扫描所有实体
  • Stage 2 Registry 构建 — 为 Stage3 准备注册表
  • Stage 3 NecessityGrader（LLM）— 重要性评分
  • Stage 4 TransitionAnnotator（LLM）— 状态逐帧标注
  • Stage 5 CrossValidator — 一致性校验
  • Stage 6 Repairer（LLM）— 错误修复
  • Stage 7 最终校验 → 写入 transitions/
OUT
输出：<小说名>.wpkg（zip 包）
包含 metadata.json · events/ · lorebook/ · transitions/ · source/ · debug/

3.2 运行时游玩主流程

setup 阶段

SetupOrchestrator
生成开场叙事，建立场景

confrontation 阶段

玩家行动循环
冲突深化 / 偏离引导

resolution 阶段

ResolutionOrchestrator
事件收尾 / 切换下一 Event

1
POST /api/game/start → GameEngine.new_game()
定位主角（importance=protagonist）→ 加载第一个 Event → 初始化状态（phase=setup, turn=0）→ 清空 L0/L1/delta_state
event: state 早期快照（phase / eventId / turn）
event: chunk 开场叙事文本流
event: done 流结束
2
POST /api/game/action → GameEngine.process_input(action)
run_in_executor 异步转线程，on_narrative_chunk 回调实时流出文本
  • ① ContextEnrichmentAgent — HistoryRecaller 召回 + EntityRecognizer 识别 + LorebookQuery 检索
  • ② DeviationGuidanceAgent — DeviationController 判断偏离程度，生成引导策略
  • ③ DeltaLifecycleAgent — 更新 DeltaStateManager，记录平行时间线变化
  • ④ NarrativeGenerationAgent — UnifiedWriter 综合所有上下文生成叙事，on_narrative_chunk() 流出
  • ⑤ SceneAdaptationAgent — SceneAdapter 分析时空变化，BridgePlanner 规划衔接
  • ⑥ MemoryCompressionAgent（按阈值触发）— L0 → L1 压缩
3
并行 TTS 合成（若开启）
SentenceBuffer 凑整句 → asyncio.create_task(edge-tts) → audio_hold 按序号重排 → base64 编码
event: chunk "...文本片..." event: audio {index, audio} event: state（最终快照） event: done
4
awaiting_next_event = true → POST /api/game/continue
切换到下一个 Event → phase 重置为 setup → ResolutionOrchestrator 生成过渡叙事 → 循环回步骤 1
5
存档 / 读档
存档：POST /api/game/save → 序列化 11 个状态字段到 saves/slot_N.json
读档：POST /api/game/load → 反序列化 + 校验必填字段 + 重建运行时状态 → 直接返回 JSON（不走 SSE）

Agent 系统

6 个 Agent 族，每次玩家行动的协作链路

所有 Agent 继承 BaseLLMCaller，必须实现： @property prompt_file → @property response_model（Pydantic 结构化输出）， 通过 AgentExecutor 注册表统一调度

NarrativeGeneration

UnifiedWriter + 相位编排器（setup / confrontation / resolution），根据全部上下文生成流式叙事文本，是最核心的写作 Agent

streaming

ContextEnrichment

三子 Agent 协作：HistoryRecaller 召回相关历史、EntityRecognizer 识别行动实体、LorebookQuery 检索角色/地点/道具信息

context

DeviationGuidance

DeviationController 判断玩家行动偏离原著的程度，生成 DeviationAnalysis，引导叙事回归或拥抱平行时间线

guidance

MemoryCompression

L0Compressor 压缩近期对话为短期摘要，L1Compressor 将多个 L0 合并为长期记忆，解决 LLM 上下文窗口限制

memory

SceneAdaptation

SceneAdapter 分析空间/时间场景变化，BridgePlanner 规划场景转换衔接方案，保证叙事连贯性

scene

DeltaLifecycle

管理 DeltaStateManager 的状态转换生命周期，追踪每次行动后世界状态相对于原著的偏差量

state

记忆压缩机制

三级记忆层解决 LLM 上下文窗口限制

近期原文

最近 N 轮对话完整记录，直接放入 prompt 上下文

→

L0 摘要

L0Compressor（LLM）将超出阈值的近期轮次压缩为中期摘要

→

L1 摘要

L1Compressor（LLM）将多个 L0 合并为长期记忆，L0 列表清空

# UnifiedWriter 构建 prompt 上下文的顺序
L1摘要（最远历史，高度压缩）
  + L0摘要（中期事件，适度压缩）
  + 近期对话（原文，最近 N 轮）
  → 送入 LLM 生成叙事
压缩触发条件均在 llm_config.yaml 中配置，压缩结果序列化到存档（l0_summaries / l1_summaries 字段），读档后完整恢复记忆链。
